# 螺丝缺失检测（YOLOv8 模型 + C 主程序）

对视频里的零件逐个编号，统计每个零件的螺丝数量，判断是否缺螺丝，最后汇总有几个零件缺螺丝。

## 文件说明

| 文件 | 作用 |
| --- | --- |
| `screw_best.pt` | 训练好的 YOLOv8 模型（类别：0=bolt 螺丝，1=nut 螺母） |
| `screw_check.c` | C 程序源码，使用时从此生成exe后运行即可 |
| `screw_detect.py` | 推理脚本，由 C 程序自动调用，逐帧输出检测数量 |
| `screw_report.txt` | 运行结束后自动生成的文字结果 |
| `screw_detections.csv` | 逐帧检测明细（帧号,数量），排查问题用 |

C 语言本身不能直接加载 PyTorch 模型，所以采用「C 主程序 + Python 推理」的分工：C 负责交互、切分零件、统计与判定，Python 只负责用 YOLOv8 把每帧的螺丝框数数出来，写到 csv 里交给 C。

## 运行环境

- Python 环境：`\python\YOLO\venv`（已装 ultralytics / torch / opencv）
- 程序查找 python 的顺序：环境变量 `SCREW_PYTHON` → `..\venv\Scripts\python.exe` → 同目录 `python.exe` → 系统 PATH
- 有显卡时会自动用 GPU，否则用 CPU

## 使用方法

双击 `screw_check.exe`，按提示输入两项：

```
请输入单体螺丝数（每个零件应有的螺丝颗数）：6
请输入视频文件路径（可把视频文件直接拖进本窗口）：如F:\video\part.mp4
```

- 单体螺丝数：一个合格零件应该有几颗螺丝，填 6 就是按 6 颗判缺
- 视频路径：可以直接把视频文件拖进窗口，带空格、带中文路径都能识别
- 之后程序自动调用模型推理，逐帧统计，最后按行打印每个零件的情况

也可以用命令行参数跳过交互：

```
screw_check.exe -n 6 -v "F:\video\part.mp4" -q
```

## 输出示例

```

零件 02 | 帧 55-104 | 稳定识别 4 颗 | 应为 6 颗 | 缺 2 颗
零件 03 | 帧 115-159 | 稳定识别 6 颗 | 应为 6 颗 | 正常
----------------------------------------------------------------

缺螺丝明细：

```

## 判定逻辑

1. **零件切分**：零件是一个接一个进入画面的，零件之间的空档没有螺丝。程序统计连续为 0 的帧，一旦连续 0 的帧数达到阈值（默认 8 帧），就把前面那一段当成一个零件，后面重新开始编号。这样零件 1、2、3…按出现顺序编号。
2. **稳定状态取数**：零件刚进画面、快要离开时只有一部分螺丝可见，这些过渡帧不能算。程序在每一段里做游程统计，只保留「同一数量连续出现不少于 3 帧」的帧，取其中帧数最多的数量作为该零件的螺丝数；整段太短无法凑出稳定帧时，退回取中位数。
3. **缺螺丝判定**：`缺的数量 = 单体螺丝数 - 该零件稳定识别数量`。识别数等于单体数记「正常」，小于记「缺 N 颗」，大于记「多识别 N 颗，疑似误检」（置信度 0.2 比较低，偶尔会多检）。
4. **汇总**：末尾统计一共有几个零件、其中几个缺螺丝，并列出明细。

置信度固定为 0.2，按需求生效在推理脚本里。

## 参数速查

| 参数 | 含义 | 默认 |
| --- | --- | --- |
| `-n N` | 单体螺丝数 | 交互输入 |
| `-v PATH` | 视频路径 | 交互输入 |
| `-c VAL` | 置信度阈值 | 0.2 |
| `-g N` | 连续多少帧没识别到就切分零件 | 8 |
| `-s N` | 稳定状态要求的最短连续帧数 | 3 |
| `-t N` | 抽帧步长，2 表示隔帧处理 | 1 |
| `-k CLS` | 统计哪个类别，`auto` 只算螺丝类，也可写 `0` 或 `bolt` | auto |
| `-m PATH` | 指定模型文件 | 同目录 `screw_best.pt` |
| `-f CSV` | 直接读已有的检测 csv，跳过推理 | — |
| `-i N` | 推理分辨率 | 640 |
| `-q` | 结束后不等待回车 | — |
| `-h` | 帮助 | — |

## 速度

本机逐帧推理约 0.08～0.15 秒/帧。1 分钟 30fps 的视频（1800 帧）大约 3～5 分钟。
视频长时建议加 `-t 2` 或 `-t 3` 抽帧，速度提升 2～3 倍。注意抽帧后 `-g` 的帧数阈值也按抽帧后的帧计，例如 `-t 3` 时 `-g 8` 相当于原始视频连续 24 帧没有识别才切分。

## 已知限制

1. **完全没螺丝的零件和空档无法区分**：模型只输出螺丝框，没有零件框。如果某个零件一颗螺丝都没有，在数据上和零件之间的空档一样，会被漏掉，不会计入。需要检测这种情况，得再训练一个「零件」类别。
2. **同一画面里同时有多个零件时**：切分依赖「空档」，多零件同框时螺丝数量会叠加，编号会乱。需要逐件过画面（单件流）的场景才适用。
3. **误检与漏检**：置信度 0.2 偏低，模型偶尔会把反光、孔位当成螺丝，或漏掉被遮挡的螺丝。判定出的「多识别 N 颗，疑似误检」就是在提示这种情况；漏检会表现为缺螺丝，建议先用几段已知合格/已知缺件的视频校准 `-g`、`-s` 两个参数。
4. **抽帧**：`-t` 越大，切分和稳定判定越粗，临界情况可能判错，优先用 `-t 1`。

## 运行痕迹

- 推理时会在系统临时目录建一个 `screw_work` 工作目录放缓存，不碰项目文件
- 系统临时目录不可写时会退到程序目录下的 `cache` 子目录，运行结束自动清理
- 每次运行会覆盖 `screw_detections.csv` 与 `screw_report.txt`

## 已验证的情况

- 合成检测数据 6 组：两件全合格 / 中间件缺 2 颗 / 进入画面时数量从 1 递增 / 单帧抖动 / 只有 2 帧的短段 / 全零帧，输出均符合预期
- 端到端 2 段测试视频（3 个零件：6、6、6 与 6、4、6），模型逐帧推理后正确输出 3 个零件、1 个缺 2 颗

- 交互输入（输入数字 + 拖入路径）与命令行参数两种方式均验证通过
